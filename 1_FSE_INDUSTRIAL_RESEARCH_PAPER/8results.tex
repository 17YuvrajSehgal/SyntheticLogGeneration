\section{Results}
\label{sec:results}

We organize results around four research questions (RQ1--RQ4) using a downstream next-event prediction task. Unless otherwise stated, models are evaluated on the held-out real test split (\texttt{real\_test.npz}), and we report macro-F1 as the primary metric, with accuracy and Top-5 accuracy as secondary metrics.

\subsection{RQ1: For which workload types can synthetic data effectively double training dataset size?}
\label{sec:rq1}

To evaluate the practical utility of synthetic data augmentation, we simulate a scenario where real data collection is expensive and we seek to double the training dataset size using synthetic data. We compare downstream task performance when training on: (i) \textbf{Real-only (50\% data)}: baseline using only real training data, and (ii) \textbf{Combined (100\% data)}: 50\% real + 50\% constraint-repaired synthetic data. This setup quantifies the performance trade-off for doubling dataset size with synthetic augmentation.

\noindent\textbf{Key Findings}:

\noindent\textbf{(1) Workload-dependent effectiveness.} Synthetic data augmentation exhibits strong workload dependence. At L=4096, scimark2 achieves 87.2\% F1-Macro with 2$\times$ data, only 2.6 percentage points below the real-only baseline (89.8\%). This demonstrates that for deterministic, structured workloads (scientific computing, numerical benchmarks), synthetic augmentation can be production-viable with minimal quality loss. In contrast, I/O-heavy workloads (stream, iozone, unpack-linux) show significant degradation (25--51\%), indicating that non-deterministic I/O patterns remain challenging for diffusion-based generation.

\noindent\textbf{(2) Context length is critical.} Increasing context length from L=256 to L=4096 reduces average F1 loss from -38.1\% to -17.7\%, demonstrating that longer temporal context significantly improves synthetic data quality. scimark2 shows the largest improvement, with degradation decreasing from -31.4\% (L=256) to -2.6\% (L=4096). This suggests that L=4096 should be the minimum context length for practical synthetic data generation.

\noindent\textbf{(3) Practical trade-off framework.} Our results provide a decision framework for practitioners: (i) For deterministic workloads (scimark2, pybench @ L=4096), synthetic augmentation is acceptable with $<$11\% F1 loss, (ii) For complex I/O workloads (ffmpeg @ L=4096), augmentation may be viable for non-critical tasks with $\sim$17\% loss, and (iii) For non-deterministic I/O benchmarks (stream, iozone), augmentation is not recommended with $>$25\% loss.

\noindent\textbf{Takeaway}: Synthetic data augmentation is \textit{workload-dependent}. It works well for deterministic, structured workloads but struggles with non-deterministic I/O patterns. The scimark2 result (87.2\% F1, only -2.6\% loss) proves that diffusion models can generate production-quality synthetic data under the right conditions, identifying clear boundaries for when synthetic augmentation is viable.
