\section{Experimental Setup}
\label{sec:experiments}

This section describes the compute environment, datasets, experimental design, and sampling procedure used to evaluate the proposed diffusion-based kernel trace generator. All experiments use a unified training and generation pipeline and differ only in controlled variables such as temporal context length and feature availability.

\subsection{Compute Environment and Datasets}

All experiments were executed on the Nibi high-performance computing cluster. Each training and sampling job was allocated a single NVIDIA H100 GPU with 80\,GB of device memory, along with 8 CPU cores and 32\,GB of host memory. Mixed-precision training with \texttt{bf16} and TF32 acceleration was enabled to maximize throughput and maintain numerical stability on H100-class hardware.

We use windowed NPZ datasets derived from real LTTng kernel traces, as described in Section~\ref{sec:windowing}. Each dataset consists of fixed-length sequences extracted from the \texttt{all-events} tracing configuration and split into training, validation, and test partitions. Unless otherwise stated, experiments are conducted on the \texttt{scimark2} benchmark, which exhibits a diverse mix of compute, scheduling, and memory behavior and is commonly used in systems performance analysis.

\subsection{Model and Training Configuration}
\label{sec:model-config}

All experiments use the same diffusion-model architecture in order to isolate the effects of data representation and temporal context. The denoising network is a Transformer encoder with $d_{\text{model}}=256$, 4--8 attention heads, and 4--8 layers depending on configuration. The diffusion process uses $T=1000$ timesteps with a linear noise schedule from $\beta_{\text{start}}=10^{-4}$ to $\beta_{\text{end}}=0.02$. Optimization is performed using AdamW with an initial learning rate of $2 \times 10^{-4}$ and a cosine annealing schedule. Aside from the experimental variables described below, all architectural and optimization hyperparameters are held constant across runs.

\subsection{Experimental Design}

We conduct two complementary experimental studies: a \emph{context-length study} to evaluate scalability with respect to temporal context, and a \emph{feature ablation study} to quantify the contribution of system-level metadata.

\paragraph{Context-Length Study.}
To assess the impact of temporal context on generative fidelity, we train separate models using the full feature set (\texttt{event}, \texttt{dt}, \texttt{cpu}, \texttt{tid}, \texttt{comm}, \texttt{ret}) at three fixed sequence lengths: short (256), medium (1024), and long (4096). Batch sizes are adjusted per configuration to fit GPU memory constraints while maintaining comparable token throughput.

This design enables a controlled comparison of short- and long-range dependency modeling while keeping all other architectural and optimization factors constant.

\paragraph{Feature Ablation Study.}
To isolate the effect of feature availability, we conduct a feature ablation study at a fixed sequence length of $L=4096$. We select $L=4096$ for two reasons, (i) the longest context configuration to maximize the model's ability to capture long-range dependencies and complex system behavior patterns (ii) the results from context-length study showed that it outperforms other configuration. This choice also ensures that any observed differences in downstream performance can be attributed to feature availability rather than insufficient temporal context. Since context length is evaluated independently in the context-length study, fixing $L=4096$ prevents confounding the impact of feature removal with changes in temporal context.

\subsection{Sampling and Synthetic Data Generation Protocol}

For each trained model, we generate synthetic kernel traces using the reverse diffusion process. Sampling employs DDIM with 50 steps starting from Gaussian noise. For consistency, models are re-instantiated with the same architectural hyperparameters used during training, and the corresponding checkpoints are loaded. Discrete channels are decoded using argmax over predicted logits, while continuous time-delta values are generated directly from the model output.

Synthetic traces are generated for all context-length and feature-ablation configurations and stored in the same windowed NPZ format as the real traces. For each configuration, we generate 10,000 synthetic samples to match the scale of real training data. These generated traces are evaluated through downstream task performance to assess how training and sampling configurations affect synthetic data utility.

\paragraph{Constraint reference for evaluation.}
In addition to downstream task evaluation, we assess system validity using a universal constraint knowledge base learned from the complete set of real NPZ shards (train/validation/test across dataset variants) using parallel processing with up to 32 workers. All reported validity scores and repair experiments use the same \texttt{constraints\_universal.json} file to ensure consistent and reproducible assessment across models and configurations.

\subsection{Downstream Task Evaluation}
\label{sec:downstream-eval}

To evaluate the utility of synthetic data, we employ a next-event prediction task. This task measures whether models trained on synthetic data can accurately predict real system behavior.

\paragraph{Task Definition.} Given a sequence of $L_{\text{pred}}=128$ consecutive kernel events, the model predicts the next event type (384-way classification). This task requires understanding both local event patterns and longer-range dependencies in system execution.

\paragraph{Predictor Architecture.} The downstream predictor is a Transformer-based classifier with $d_{\text{model}}=256$, 8 attention heads, and 4 layers. For multi-channel inputs, features are embedded separately (event: $d/6$, others: $d/12$ each), concatenated, and fused to $d_{\text{model}}$ via a linear layer. Positional encodings are added, and the final hidden state is passed through a two-layer MLP to produce event logits. For ablation studies, we use \texttt{FlexibleNextEventPredictor}, which supports arbitrary channel subsets.

\paragraph{Training Configuration.} Predictors are trained for up to 20 epochs using AdamW ($\text{lr}=10^{-4}$) with cross-entropy loss. Training employs sliding windows with stride 64 over sequences, batch size 64, and early stopping with patience 3 based on validation F1-macro score. The best checkpoint is selected for final evaluation.

\paragraph{Evaluation Metrics.} We evaluate downstream predictor performance using six complementary metrics, each capturing different aspects of prediction quality. All metrics are computed on the held-out real test set to measure how well models trained on synthetic data generalize to real system behavior.

\textbf{F1-Score (Macro).} Our primary metric is the macro-averaged F1-score, which treats all event classes equally regardless of frequency. For each event class $c$, we compute precision and recall:
\[
\text{Precision}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c}, \quad
\text{Recall}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FN}_c},
\]
where $\text{TP}_c$, $\text{FP}_c$, and $\text{FN}_c$ denote true positives, false positives, and false negatives for class $c$. The per-class F1-score is the harmonic mean:
\[
\text{F1}_c = 2 \cdot \frac{\text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c}.
\]
The macro-averaged F1-score is the unweighted mean across all $N=384$ event classes:
\[
\text{F1-macro} = \frac{1}{N} \sum_{c=1}^{N} \text{F1}_c.
\]
We select F1-macro as our primary metric because kernel traces exhibit severe class imbalance: common events (e.g., scheduler switches, memory allocations) occur orders of magnitude more frequently than rare but critical events (e.g., errors, security violations, I/O failures). Macro-averaging ensures that rare events contribute equally to the overall score, preventing models from achieving high accuracy by simply predicting frequent classes while ignoring rare but operationally significant events.

\textbf{F1-Score (Weighted).} As a secondary metric, we report weighted F1-score, which averages per-class F1 scores weighted by class support (number of true instances):
\[
\text{F1-weighted} = \frac{1}{|\mathcal{D}|} \sum_{c=1}^{N} n_c \cdot \text{F1}_c,
\]
where $n_c$ is the number of test samples with true label $c$ and $|\mathcal{D}|$ is the total test set size. This metric reflects overall prediction quality while accounting for class distribution, providing a complementary view to macro-averaging.

\textbf{Accuracy.} We report standard classification accuracy, defined as the fraction of correct predictions:
\[
\text{Accuracy} = \frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \mathbb{I}[\hat{y}_i = y_i],
\]
where $\hat{y}_i$ and $y_i$ are the predicted and true labels. While accuracy is intuitive, it can be misleading under class imbalance, as models can achieve high accuracy by overpredicting frequent classes.

\textbf{Top-K Accuracy.} To assess whether the model captures plausible alternatives even when the top prediction is incorrect, we compute top-5 and top-10 accuracy:
\[
\text{Top-K Acc} = \frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \mathbb{I}[y_i \in \text{TopK}(\mathbf{p}_i)],
\]
where $\text{TopK}(\mathbf{p}_i)$ denotes the set of $K$ event classes with highest predicted probabilities for sample $i$. These metrics are particularly relevant for kernel traces, where multiple valid next events may exist depending on runtime conditions (e.g., different scheduler decisions, I/O completion ordering).

\textbf{Cross-Entropy Loss.} We report the average cross-entropy loss to quantify prediction confidence:
\[
\text{Loss} = -\frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \log p(y_i \mid \mathbf{x}_i),
\]
where $p(y_i \mid \mathbf{x}_i)$ is the predicted probability of the true class. Lower loss indicates higher confidence in correct predictions, complementing discrete accuracy metrics with a continuous measure of prediction quality.

\paragraph{Experimental Configurations.} For each diffusion model configuration, we train downstream predictors on four datasets: (i) \textbf{Real only}---baseline using only real training data, (ii) \textbf{Synthetic only}---trained entirely on synthetic data, (iii) \textbf{Combined (repaired)}---50/50 mix of real and constraint-repaired synthetic data, and (iv) \textbf{Combined (no repair)}---50/50 mix of real and raw synthetic data. All predictors are evaluated on the same held-out real test set to measure synthetic data utility.
