# Data Processing Pipeline

This directory contains the complete data processing pipeline (Stage 1 of **TraceSynth**) for converting raw LTTng kernel traces into training-ready datasets. The pipeline transforms text traces through multiple stages: vocabulary building, Parquet conversion, NPZ windowing, constraint learning, and dataset organization.

---

## Dataset

### Source Dataset

This project uses the **LTTng Execution Traces for Ten Phoronix Benchmarks** dataset:

> Alexis Martin, V. M.-M. (2017). LTTng Execution traces for ten Phoronix benchmarks (part1) [Data set]. Zenodo. https://doi.org/10.5281/zenodo.437170

**Note**: Due to the large size of the dataset, it is not included in this repository. You must download it separately following the instructions below.

### Dataset Setup Instructions

1. **Download the Dataset**
   
   Visit the Zenodo repository and download the dataset:

2. **Extract the Dataset**
   
   Extract the downloaded archive to your working directory:
   ```bash
   tar -xzf lttng-traces-phoronix.tar.gz
   ```

3. **Organize the Raw Traces**
   
   The dataset contains LTTng trace directories. You need to convert them to text format and organize them by benchmark. Create the following directory structure:
   
   ```
   scratch/
   └── txt_traces_all_benchmarks/
       ├── compress-gzip/
       │   ├── run0.txt
       │   ├── run1.txt
       │   └── ...
       ├── ffmpeg/
       │   ├── run0.txt
       │   └── ...
       ├── ...
   ```

4. **Convert LTTng Binary Traces to Text**
   
   Use the `babeltrace` tool to convert binary LTTng traces to text format:
   ```bash
   # Install babeltrace if not already installed
   sudo apt-get install babeltrace  # Ubuntu/Debian
   # or
   brew install babeltrace  # macOS
   
   # Convert each trace directory to text
   # Example for a single trace:
   babeltrace /path/to/lttng-trace-directory > scratch/txt_traces_all_benchmarks/compress-gzip/run0.txt
   ```
   
   Repeat this process for all benchmark runs to populate the `txt_traces_all_benchmarks` directory.

5. **Verify the Setup**
   
   Ensure your directory structure matches the expected format:
   ```bash
   ls -R scratch/txt_traces_all_benchmarks/
   ```
   
   Each benchmark folder should contain multiple `.txt` files (one per run).

### Expected Directory Structure

After setup, your workspace should have:

```
SyntheticLogGeneration/
├── data_processing/          # This directory (scripts)
├── dataset/                  # Generated metadata and vocabularies
│   └── metadata_all_events/
```

**Important**: The `scratch/` directory is excluded from version control (`.gitignore`) due to its large size.

## Data Formats

### 1. Raw Text Traces (`.txt`)
**Location**: `scratch/txt_traces_all_benchmarks/<benchmark>/<run>.txt`

LTTng kernel trace files in text format with the following structure:
```
[HH:MM:SS.ns] (+delta) hostname event_name: { cpu_id = X }, { key1 = val1, key2 = val2, ... }
```

### 2. Enriched Parquet (`.parquet`)
**Location**: `scratch/enriched_parquet/<benchmark>/<run>.parquet`

**Schema**: Hybrid design balancing query performance with data fidelity.

#### Core Columns (Always Present)
| Column | Type | Description |
|--------|------|-------------|
| `line_idx` | `int64` | Original line number (0-indexed) |
| `ts_str` | `string` | Raw timestamp (HH:MM:SS.ns) |
| `delta_s` | `float64` | Time since previous event (seconds) |
| `t_rel_ns` | `int64` | Cumulative relative time (nanoseconds) |
| `event_name` | `string` | Kernel event name (e.g., `sched_switch`) |
| `event_id` | `int32` | Integer ID from `vocab.json` |
| `cpu_id` | `int32` | CPU core ID |

#### First-Class Payload Columns (Sparse/Nullable)
| Column | Type | Description |
|--------|------|-------------|
| `tid` | `int64` | Thread ID |
| `pid` | `int64` | Process ID |
| `comm` | `string` | Process command name (e.g., `python`) |
| `ret` | `int64` | Return value (syscalls) |
| `fd` | `int64` | File descriptor |
| `filename` | `string` | File path |
| `flags` | `string` | Event flags |
| `state` | `int64` | Process state |

#### Catch-All Column
| Column | Type | Description |
|--------|------|-------------|
| `extra_params` | `string` | JSON-encoded dictionary of all other parameters |

### 3. Windowed NPZ (`.npz`)
**Location**: `scratch/windowed_npz_<SEQ_LEN>/<benchmark>/<split>/*.npz`

Compressed NumPy archives containing fixed-length sequences optimized for training.

**Arrays** (all share shape `(NumWindows, SeqLen)`):

| Key    | Type      | Shape  | Description     | Processing |
|--------|-----------|--------|-----------------|------------|
| `event`| `int32`   | `(N,L)`| Event ID        | From `vocab.json` |
| `dt`   | `float32` | `(N,L)`| Time delta      | Log-normalized: `log(1 + Δt)` |
| `cpu`  | `int8`    | `(N,L)`| CPU core ID     | Raw value |
| `tid`  | `int16`   | `(N,L)`| Thread ID       | Hashed: `tid % 256` |
| `fd`   | `int16`   | `(N,L)`| File descriptor | Clamped: values ≥ 1024 → 1024 |
| `comm` | `int16`   | `(N,L)`| Command name    | From `vocab_comm.json` |
| `ret`  | `int16`   | `(N,L)`| Return value    | From `vocab_ret.json` |

**Windowing**: Sliding window with configurable length `L` and stride `S` (typically `L=1024`, `S=512`).


### 4. Constraints JSON
**Location**: `dataset/constraints_universal.json`

Learned invariants from real traces used for validation and repair:

```json
{
  "allowed_transitions": {
    "event_id": ["list_of_valid_next_events"]
  },
  "dt_constraints": {
    "event_id": {
      "min": "float",
      "max": "float",
      "allowed_set": ["observed_values"]
    }
  },
  "allowed_cpus": ["global_cpu_list"],
  "event_cpu_constraints": {
    "event_id": ["allowed_cpus"]
  },
  "event_tid_constraints": {
    "event_id": ["allowed_tid_buckets"]
  },
  "event_fd_constraints": {
    "event_id": ["allowed_fds"]
  },
  "event_comm_constraints": {
    "event_id": ["allowed_comm_ids"]
  },
  "event_ret_constraints": {
    "event_id": ["allowed_ret_ids"]
  },
  "event_probs": {
    "event_id": "probability"
  }
}
```

## Scripts

### 1. `build_vocab.py`
**Purpose**: Build global event vocabulary from raw text traces.

**Input**: Raw `.txt` trace files  
**Output**: 
- `vocab.json`: `{event_name: event_id}`
- `id_to_event.json`: `{event_id: event_name}`
- `vocab_stats.json`: Counts and metadata

**Usage**:
```bash
python data_processing/build_vocab.py \
  --root /path/to/txt_traces_all_benchmarks \
  --glob "*-all-events-run*.txt" \
  --out_dir dataset/metadata_all_events \
  --min_count 1 \
  --sort freq
```

**Arguments**:
- `--root`: Root directory containing text traces
- `--glob`: Pattern to match trace files (default: `*-all-events-run*.txt`)
- `--out_dir`: Output directory for vocabularies (default: `metadata`)
- `--min_count`: Minimum event occurrence threshold (default: 1)
- `--sort`: Ordering method - `freq` (by frequency) or `alpha` (alphabetically)
- `--max_lines_per_file`: Debug option to limit lines scanned per file

**Details**: Extracts event names using regex pattern matching, counts occurrences across all files, and assigns integer IDs. Events sorted by frequency get lower IDs (common in NLP).

---

### 2. `txt_to_enriched_parquet.py`
**Purpose**: Convert raw text traces to structured Parquet format with hybrid schema.

**Input**: Raw `.txt` trace file + `vocab.json`  
**Output**: Enriched `.parquet` file

**Usage**:
```bash
python data_processing/txt_to_enriched_parquet.py \
  --input /path/to/trace.txt \
  --output /path/to/output.parquet \
  --vocab dataset/metadata_all_events/vocab.json \
  --batch-size 200000
```

**Arguments**:
- `--input`: Input text trace file
- `--output`: Output Parquet file path
- `--vocab`: Path to `vocab.json`
- `--batch-size`: Rows per batch for streaming writes (default: 200,000)

**Details**: 
- Parses text lines using regex to extract timestamps, deltas, event names, and payloads
- Maps event names to IDs using vocabulary
- Extracts first-class columns (`tid`, `comm`, `ret`, etc.) into dedicated fields
- Stores remaining parameters in JSON-encoded `extra_params` column
- Handles missing deltas (marked with `?`) by setting to 0.0
- Computes monotonic relative time in nanoseconds
- Streams data in batches for memory efficiency
- Uses ZSTD compression and dictionary encoding

---

### 3. `build_training_vocabs.py`
**Purpose**: Build vocabularies for `comm` and `ret` fields from Parquet files.

**Input**: Directory of `.parquet` files  
**Output**: 
- `vocab_comm.json`: Full vocabulary for command names
- `vocab_ret.json`: Top-K vocabulary for return values

**Usage**:
```bash
python data_processing/build_training_vocabs.py \
  --parquet-dir /path/to/enriched_parquet \
  --output-dir dataset/metadata_all_events \
  --top-k-ret 1024
```

**Arguments**:
- `--parquet-dir`: Root directory containing Parquet files (recursive search)
- `--output-dir`: Output directory for vocabularies
- `--top-k-ret`: Maximum vocabulary size for return values (default: 1024)

**Details**:
- Scans all Parquet files recursively
- Builds complete vocabulary for `comm` (process names are limited)
- Builds Top-K vocabulary for `ret` to handle long-tail distribution
- Reserves ID 0 for `<PAD>` and ID 1 for `<UNK>`
- Reports coverage percentage for return value vocabulary
- Sorts by frequency for deterministic ordering

---

### 4. `parquet_to_windowed_npz.py`
**Purpose**: Convert Parquet files to windowed NPZ sequences for training.

**Input**: Directory of `.parquet` files + training vocabularies  
**Output**: Windowed `.npz` files organized by train/val/test splits

**Usage**:
```bash
python data_processing/parquet_to_windowed_npz.py \
  --input-dir /path/to/enriched_parquet \
  --output-dir /path/to/windowed_npz_1024 \
  --vocab-dir dataset/metadata_all_events \
  --seq-len 1024 \
  --stride 512 \
  --split-ratio 0.8,0.1,0.1
```

**Arguments**:
- `--input-dir`: Directory containing Parquet files (recursive)
- `--output-dir`: Output root for NPZ dataset
- `--vocab-dir`: Directory containing `vocab_comm.json` and `vocab_ret.json`
- `--seq-len`: Sequence length for windows (default: 1024)
- `--stride`: Stride for sliding window (default: 512)
- `--split-ratio`: Train/val/test ratio (default: `0.8,0.1,0.1`)

**Details**:
- **Tokenization**: Maps `comm` and `ret` strings to integer IDs using vocabularies
- **Normalization**: Applies `log1p(dt)` to time deltas
- **Hashing**: Reduces TID to buckets via `tid % 256`
- **Clamping**: Caps file descriptors at 1024
- **Windowing**: Slides window of length `L` with stride `S` over traces
- **Splitting**: Randomly assigns files to train/val/test using deterministic seed (42)
- **Compression**: Saves using `np.savez_compressed`
- Skips files shorter than sequence length

---

### 5. `organize_shards.py`
**Purpose**: Reorganize NPZ shards from flat split structure to benchmark-organized structure.

**Input**: `root/{train,val,test}/*.npz`  
**Output**: `root/<benchmark>/{train,val,test}/*.npz`

**Usage**:
```bash
python data_processing/organize_shards.py [dir1] [dir2] ...

# Or use environment variable:
python data_processing/organize_shards.py  # Uses $SCRATCH/windowed_npz_{256,1024,4096}
```

**Arguments**:
- `dirs`: List of root directories to organize (optional, defaults to `$SCRATCH` paths)

**Details**:
- Extracts benchmark name from filename (prefix before `-all-events`)
- Moves files from `root/split/file.npz` to `root/benchmark/split/file.npz`
- Creates target directories automatically
- Removes empty split directories after reorganization
- Uses progress bar for tracking
- Handles multiple directories in batch

---

### 6. `learn_constraints.py`
**Purpose**: Learn kernel trace invariants from real data for validation and repair.

**Input**: NPZ shard files (windowed dataset)  
**Output**: `constraints.json` containing learned rules

**Usage**:
```bash
python data_processing/learn_constraints.py \
  --real_glob "dataset/window_shards/**/*.npz" \
  --output dataset/constraints_universal.json \
  --num_events 384 \
  --num_cpus 4 \
  --workers 16
```

**Arguments**:
- `--real_glob`: Glob pattern for real training shards (recursive)
- `--output`: Path to save constraints JSON
- `--num_events`: Vocabulary size of event IDs (default: 384)
- `--num_cpus`: Number of CPU cores in system (default: 4)
- `--workers`: Number of parallel workers (default: all available CPUs, capped at 32)

**Details**:
- **Multiprocessing**: Processes shards in parallel for efficiency
- **Learned Invariants**:
  1. **Transition Graph**: Valid event sequences (E_t → E_{t+1})
  2. **Temporal Bounds**: Min/max/allowed time deltas per event
  3. **CPU Affinity**: Which CPUs can trigger each event
  4. **Thread Identity**: Allowed TID buckets per event
  5. **Semantic Context**: Allowed `comm`, `fd`, `ret` values per event
- **Aggregation**: Combines partial results from all shards
- **Output**: JSON file used by validation and repair modules
- Uses `tqdm` for progress tracking

---

### 7. `extract_event_schemas.py`
**Purpose**: Extract parameter schemas for each event type from raw traces.

**Input**: Directory of raw `.txt` trace files  
**Output**: `event_schemas.json` containing parameter signatures

**Usage**:
```bash
python data_processing/extract_event_schemas.py \
  --dir /path/to/txt_traces_root \
  --out dataset/event_schemas.json
```

**Arguments**:
- `--dir`: Root directory containing text trace files (recursive search)
- `--out`: Path to output JSON registry

**Details**:
- Parses each line to extract event name and parameter keys
- Groups parameters into signatures (sorted, unique sets)
- Counts occurrences of each signature variant
- Outputs registry mapping events to their parameter schemas
- Useful for understanding event structure and variability
- Excludes directories containing "parquet" in path
- Handles large files with progress updates every 500K lines

**Output Format**:
```json
{
  "event_name": [
    {
      "signature_id": 0,
      "fields": ["cpu_id", "param1", "param2"],
      "count": 12345
    }
  ]
}
```

## Complete Pipeline Execution

To process a new dataset from scratch:

```bash
# Step 1: Build event vocabulary
python data_processing/build_vocab.py \
  --root /path/to/txt_traces_all_benchmarks \
  --glob "*-all-events-run*.txt" \
  --out_dir dataset/metadata_all_events \
  --sort freq

# Step 2: Convert text traces to Parquet (run for each trace file)
python data_processing/txt_to_enriched_parquet.py \
  --input /path/to/trace.txt \
  --output /path/to/output.parquet \
  --vocab dataset/metadata_all_events/vocab.json

# Step 3: Build training vocabularies from Parquet
python data_processing/build_training_vocabs.py \
  --parquet-dir /path/to/enriched_parquet \
  --output-dir dataset/metadata_all_events

# Step 4: Generate windowed NPZ shards
python data_processing/parquet_to_windowed_npz.py \
  --input-dir /path/to/enriched_parquet \
  --output-dir dataset/windowed_npz_1024 \
  --vocab-dir dataset/metadata_all_events \
  --seq-len 1024 \
  --stride 512

# Step 5: Organize shards by benchmark
python data_processing/organize_shards.py dataset/windowed_npz_1024

# Step 6: Learn constraints from organized dataset
python data_processing/learn_constraints.py \
  --real_glob "dataset/windowed_npz_1024/**/*.npz" \
  --output dataset/constraints_universal.json \
  --num_events 384
```

## Metadata Files

The pipeline generates and uses several metadata files:

### Event Vocabularies
- **`vocab.json`**: Event name → Event ID mapping
- **`id_to_event.json`**: Event ID → Event name mapping
- **`vocab_stats.json`**: Statistics (counts, top events)

### Training Vocabularies
- **`vocab_comm.json`**: Command name → ID mapping (includes `<PAD>`, `<UNK>`)
- **`vocab_ret.json`**: Return value → ID mapping (Top-K, includes `<PAD>`, `<UNK>`)

### Constraints
- **`constraints_universal.json`**: Learned invariants for validation/repair

### Event Schemas (Optional)
- **`event_schemas.json`**: Parameter signatures for each event type

## Notes

### Data Splits
- **Train/Val/Test**: Default ratio is 80/10/10
- Files are randomly shuffled with deterministic seed (42) for reproducibility
- Split is at the file (run) level to prevent data leakage

### Memory Efficiency
- Parquet conversion uses streaming writes with configurable batch size
- NPZ generation pre-allocates arrays to avoid memory fragmentation
- Constraint learning uses multiprocessing with automatic worker management

### Special Values
- **Padding**: `0` for most integer fields
- **Unknown**: `1` for vocabulary lookups (`<UNK>`)
- **Missing FD**: Mapped to `fd_cap` (1024)
- **Missing Delta**: Set to `0.0` when marked with `?`
