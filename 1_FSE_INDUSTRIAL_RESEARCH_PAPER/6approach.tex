\section{Approach}
\label{sec:approach}
\paragraph{Industrial Motivation.}
Kernel execution traces are a foundational artifact for a wide range of system-analysis tools, including performance debugging, anomaly detection, and regression testing of trace-driven infrastructure. In production environments, however, collecting large volumes of kernel traces is often constrained by storage overhead, runtime impact, and operational or privacy policies. As a result, engineers frequently operate with limited or skewed trace datasets, which hinders the development and stress-testing of trace-driven tools across diverse workloads. \textsc{SynthTrace} addresses this gap by generating invariant-preserving synthetic kernel traces that can safely substitute for or augment real traces in downstream system-analysis workflows.

\paragraph{Why Engineers Care.}
Kernel traces are widely used by engineers to develop and validate trace-driven system analysis tools, such as performance anomaly detectors, workload characterization models, and predictive debugging utilities. In practice, these tools are often trained and evaluated on limited trace datasets collected under a small number of workloads or execution conditions, which reduces their robustness to rare scheduling patterns and long-tail behaviors. \textsc{SynthTrace} enables engineers to augment existing trace datasets with invariant-preserving synthetic executions, allowing them to stress-test trace consumers, evaluate model generalization, and explore system behaviors that are costly or impractical to observe repeatedly in production.

Figure~\ref{fig:architecture} presents the \textsc{SynthTrace} pipeline, which consists of four stages:
(1) pre-processing of real data to transform raw kernel traces into structured, reproducible representations,
(2) probabilistic sequence modeling to capture recurring execution patterns and attribute correlations observed in real kernel traces, and synthetic trace generation,
(3) constraint-guided validation and repair to enforce kernel-level execution invariants.
(4) at last, run downstream training to evaluate the performance of synthetic traces
Together, these stages prioritize robustness, semantic correctness, and safe downstream reuse over model-specific optimizations.

\subsection{Data Preprocessing}
\label{sec:data-preprocessing}

This section describes the preprocessing pipeline that converts raw kernel traces into ML-ready representations.

\subsubsection{Dataset and Trace Extraction}
\label{sec:trace-extraction}

We use kernel execution traces from the LTTng dataset introduced by Martin et al.~\cite{martin2017lttng}, which contains traces for nine Phoronix benchmarks spanning CPU-intensive, memory-intensive, and I/O-heavy workloads. We focus on six benchmarks (\emph{ffmpeg}, \emph{iozone}, \emph{pybench}, \emph{scimark2}, \emph{stream}, \emph{unpack-linux}) using the \emph{all-events} configuration, which captures kernel-level events across the entire operating system. Each benchmark provides 32 independent runs.

Raw LTTng traces are decoded using the \texttt{babeltrace2} toolchain into human-readable text logs. Each event records a high-resolution timestamp, inter-event time delta, CPU core, and event-specific metadata. An example excerpt:

\begin{verbatim}
[08:46:31.491346508] (+?.?????????) flutin kmem_kmalloc:
{ cpu_id = 1 }, { call_site = 0xFFFFFFFFA09A81A7,
  ptr = 0xFFFF880789E9B800, bytes_req = 739,
  bytes_alloc = 1024 }

[08:46:31.491349294] (+0.000002786) flutin kmem_kfree:
{ cpu_id = 1 }, { call_site = 0xFFFFFFFFA09A827A,
  ptr = 0xFFFF880789E9B800 }

[08:46:31.491349830] (+0.000000536) flutin sched_waking:
{ cpu_id = 1 }, { comm = "lttng-consumerd",
  tid = 2208, prio = 20, target_cpu = 2 }
\end{verbatim}

\subsubsection{Multi-Channel Event Representation}
\label{sec:multi-channel}
Rather than modeling only event types, we extract a comprehensive multi-channel representation that captures both temporal and system-level context. Each kernel event is represented by six channels: (i) \texttt{event}---the event type identifier, (ii) \texttt{dt}---the inter-event time delta in seconds, (iii) \texttt{cpu}---the CPU core identifier, (iv) \texttt{tid}---the thread identifier, (v) \texttt{comm}---the process command name, and (vi) \texttt{ret}---the return value for system calls. This multi-modal representation enables the model to learn correlations between event semantics, timing patterns, and system resource allocation, which are critical for generating realistic synthetic traces.

At this stage, the output of preprocessing is a cleaned, time-ordered textual representation of kernel events with extracted multi-channel attributes, serving as an intermediate format between raw LTTng traces and the machine-learning-ready data structures described next.





\subsubsection{Vocabulary Construction and Structured Storage}
\label{sec:parquet}

To enable consistent numeric encoding across all experiments, we construct global vocabularies by scanning all decoded traces and assigning deterministic integer identifiers to categorical values. Event names are ordered by decreasing frequency, yielding 384 unique kernel event types. We similarly construct vocabularies for process command names (\texttt{comm}, 123 entries) and return values (\texttt{ret}, 1026 entries). All vocabularies include special tokens for padding and unknown values, and are frozen once constructed.

\paragraph{Structured Storage.}
The decoded text traces are converted into Apache Parquet format for efficient storage and access. Each trace run yields one Parquet file containing event-level records with core fields (timestamp, event type, CPU, inter-event delta) and payload attributes (thread ID, process command, return value). This columnar representation enables scalable preprocessing and serves as input to the windowing stage.

\subsubsection{Windowed Sequence Construction}
\label{sec:windowing}

Kernel traces are long, variable-length streams, whereas sequence models require fixed-length inputs. We segment each Parquet trace into overlapping fixed-length windows using a sliding window approach. Event identifiers and CPU identifiers are preserved as categorical values. Inter-event time deltas (\texttt{dt}) are log-normalized using $\log(1 + \Delta t)$ to reduce scale variance. Thread identifiers are hashed into 256 buckets to control cardinality. Categorical fields (\texttt{comm}, \texttt{ret}) are mapped using the frozen vocabularies.

We generate windowed datasets at three sequence lengths ($L \in \{256, 1024, 4096\}$) to enable systematic evaluation of short-, medium-, and long-context models. Each window contains aligned tensors for all six channels with shape $(N, L)$, where $N$ is the number of windows and $L$ is the sequence length. The resulting datasets are stored as compressed NumPy archives (\texttt{.npz}) and serve as the final machine-learning-ready input for all experiments.








\subsection{Diffusion Model Architecture}
\label{sec:diffusion-model}

\textsc{SynthTrace} uses a Transformer-based denoising diffusion model to generate multi-channel kernel traces. Each windowed trace $\mathbf{x}$ of length $L$ contains six channels: \texttt{event}, \texttt{cpu}, \texttt{tid}, \texttt{comm}, \texttt{ret}, and \texttt{dt}. Discrete channels are embedded via learned tables $E_c \in \mathbb{R}^{|V_c| \times d}$, while the continuous time-delta channel is projected via an MLP. At each position, embeddings are summed to form a unified latent representation:
\[
\mathbf{h}_0[i] = \sum_{c \in \mathcal{C}_{\text{disc}}} E_c(x_c[i]) \;+\; \mathrm{MLP}_{dt}(x_{dt}[i]),
\quad \mathbf{h}_0 \in \mathbb{R}^{L \times d}.
\]


The forward diffusion process progressively corrupts $\mathbf{h}_0$ with Gaussian noise over $T$ timesteps:
\[
\mathbf{h}_t = \sqrt{\bar{\alpha}_t}\,\mathbf{h}_0 + \sqrt{1-\bar{\alpha}_t}\,\boldsymbol{\epsilon},
\quad \boldsymbol{\epsilon} \sim \mathcal{N}(0, I),
\]
where $\bar{\alpha}_t = \prod_{s=0}^{t}\alpha_s$ and $\{\alpha_t\}$ follow a linear $\beta$-schedule. The reverse process uses a Transformer encoder $\epsilon_{\theta}$ to predict the noise. Timestep conditioning is added via sinusoidal embeddings:
\[
\mathbf{t}_{\text{emb}} = \mathrm{MLP}_{\text{time}}(\mathrm{SinEmb}(t)), \quad
\hat{\boldsymbol{\epsilon}} = \epsilon_{\theta}(\mathbf{h}_t + \mathbf{t}_{\text{emb}}).
\]

The training objective combines a standard diffusion loss with an auxiliary reconstruction loss:
\[
\mathcal{L}_{\text{latent}} = \left\lVert \hat{\boldsymbol{\epsilon}} - \boldsymbol{\epsilon} \right\rVert_2^2.
\]
To maintain semantic consistency across channels, we decode the estimated clean state $\hat{\mathbf{h}}_0 = (\mathbf{h}_t - \sqrt{1-\bar{\alpha}_t}\,\hat{\boldsymbol{\epsilon}}) / \sqrt{\bar{\alpha}_t}$ and optimize per-channel reconstruction:
\[
\mathcal{L}_{\text{recon}} = \sum_{c \in \mathcal{C}_{\text{disc}}} \mathrm{CE}(\hat{y}_c, y_c) + \mathrm{MSE}(\widehat{dt}, dt).
\]
The final objective is $\mathcal{L} = \mathcal{L}_{\text{latent}} + \lambda\,\mathcal{L}_{\text{recon}}$, where $\lambda$ weights the auxiliary term.


To generate synthetic traces, we initialize a latent sequence with Gaussian noise and iteratively apply the reverse diffusion process from $t=T-1$ to $0$. Discrete channels are decoded via argmax over logits; continuous values are output directly. Generated samples are saved for direct evaluation.




\subsection{Training Procedure}
\label{sec:training}

Models are trained on windowed NPZ trace shards using the architecture, diffusion schedule, and loss formulation described above. For each mini-batch, a diffusion timestep is sampled uniformly, noise is injected, and the Transformer denoiser predicts the injected noise. The auxiliary reconstruction loss is computed from the estimated clean latent state and jointly optimized with the diffusion objective.

We train separate models at different sequence lengths ($L \in \{256, 1024, 4096\}$) to assess how temporal context affects generation quality. Batch sizes are adjusted to fit GPU memory; all other hyperparameters remain constant. Optimization uses AdamW with cosine learning-rate decay. The best checkpoint (by validation loss) is retained for sampling and evaluation.


\subsection{Constraint Learning and Post-hoc Repair}
\label{sec:constraints-repair}

Neural generators can produce locally plausible sequences that violate kernel execution invariants (impossible event transitions, invalid CPU affinity, implausible timing). \textsc{SynthTrace} addresses this through constraint-based validation and repair using invariants mined from real traces.

We extract four constraint classes from real NPZ shards: (i) \textbf{Event transitions}—a directed graph $\mathcal{G} = (V, E)$ where $(e_i, e_j) \in E$ if $e_j$ follows $e_i$ in real traces; (ii) \textbf{Temporal bounds}—empirical min/max inter-event deltas per event type; (iii) \textbf{CPU affinity}—allowed CPU sets per event type; (iv) \textbf{Attribute validity}—allowed values for \texttt{tid}, \texttt{comm}, \texttt{ret} per event type. Constraints are learned once from all real data and stored as a universal reference.

\paragraph{Constraint-based distance metrics.}
We quantify synthetic trace validity using four metrics. \emph{Transition distance} measures invalid event pairs:
\[
D_{\text{trans}}(\hat{X}) = 1 - \frac{1}{|\hat{X}|-1} \sum_{t} \mathbb{I}\left[(\hat{e}_t, \hat{e}_{t+1}) \in \mathcal{G}\right].
\]
\emph{Temporal distance} measures timing violations:
\[
D_{\text{time}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\Delta t_t \notin [\min_e, \max_e]\right].
\]
\emph{CPU affinity distance} measures invalid CPU assignments:
\[
D_{\text{cpu}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\hat{cpu}_t \notin \mathcal{C}_{\hat{e}_t}\right].
\]
\emph{Attribute validity distance} aggregates categorical violations:
\[
D_{\text{attr}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\exists a \in \mathcal{A} : \hat{a}_t \notin \mathcal{V}_{\hat{e}_t}^{(a)}\right].
\]

\paragraph{Post-hoc repair.}
For each detected violation, the offending attribute is replaced by sampling from the allowed set conditioned on event type. Repair is applied uniformly as post-processing. Distances are reported before and after repair to verify invariant satisfaction.
