\section{Approach}
\label{sec:approach}

\subsection{Goals and Research Questions}
\label{sec:goals-rq}

Our primary goal is to develop a diffusion-based generative model capable of producing high-quality synthetic kernel execution traces that can augment or replace real data for downstream machine learning tasks. We evaluate synthetic data quality through the lens of a next-event prediction task, where a Transformer-based predictor is trained to forecast the next kernel event given a sequence of historical events. This downstream task serves as a proxy for measuring how well synthetic traces capture the temporal dependencies, system-level patterns, and structural constraints present in real kernel behavior.

We organize our evaluation around four research questions:

\textbf{RQ1: For which workload types can synthetic data effectively double training dataset size?} We investigate whether synthetic data can augment real training data (50\% real + 50\% synthetic) without significant performance degradation, identifying which benchmark workloads benefit from synthetic augmentation and which do not.

\textbf{RQ2: Does constraint-guided repair consistently improve synthetic data quality?} We evaluate whether post-hoc repair of constraint violations (invalid event transitions, incorrect CPU affinity) provides reliable improvements across different workloads and context lengths.

\textbf{RQ3: How does increasing diffusion model context length improve synthetic data quality?} We measure the impact of temporal context window size (L $\in$ \{256, 1024, 4096\}) on synthetic data utility, quantifying the trade-off between computational cost and quality.

\textbf{RQ4: Can simpler diffusion models (fewer channels) achieve comparable synthetic data quality with lower computational cost?} Through ablation studies, we determine whether modeling all six trace channels (event, dt, cpu, tid, comm, ret) is necessary or if simpler 2-channel (event + dt) or 4-channel models suffice.

\subsection{Dataset}
\label{sec:dataset}

We use kernel execution traces from the LTTng dataset introduced by Martin et al.~\cite{martin2017lttng}, which contains traces for nine Phoronix benchmarks: \emph{compress-gzip}, \emph{ffmpeg}, \emph{iozone}, \emph{phpbench}, \emph{pybench}, \emph{ramspeed}, \emph{scimark2}, \emph{stream}, and \emph{unpack-linux}. These benchmarks exercise diverse system behaviors (CPU-intensive, memory-intensive, I/O-heavy workloads), making them suitable for studying realistic kernel-level activity. Traces were collected on a desktop machine (Xeon E3-1225 @ 3.20GHz, 32GB RAM) using LTTng's \emph{all-events} configuration, which captures kernel-level events across the entire operating system. Each benchmark provides 32 independent runs.

Raw LTTng traces are decoded into temporally ordered sequences of kernel events, where each event records a timestamp, inter-event time delta, CPU core, and event-specific metadata. An example excerpt:

\begin{verbatim}
[08:46:31.491346508] (+?.?????????) flutin kmem_kmalloc:
{ cpu_id = 1 }, { call_site = 0xFFFFFFFFA09A81A7,
  ptr = 0xFFFF880789E9B800, bytes_req = 739,
  bytes_alloc = 1024 }

[08:46:31.491349294] (+0.000002786) flutin kmem_kfree:
{ cpu_id = 1 }, { call_site = 0xFFFFFFFFA09A827A,
  ptr = 0xFFFF880789E9B800 }

[08:46:31.491349830] (+0.000000536) flutin sched_waking:
{ cpu_id = 1 }, { comm = "lttng-consumerd",
  tid = 2208, prio = 20, target_cpu = 2 }
\end{verbatim}

From these raw traces, we extract a structured multi-channel representation for modeling.

\paragraph{Multi-Channel Representation.} Each kernel event is represented by six channels capturing both temporal and system-level context: (i) \texttt{event}---event type identifier (384 unique types across all benchmarks), (ii) \texttt{dt}---inter-event time delta in seconds, (iii) \texttt{cpu}---CPU core identifier, (iv) \texttt{tid}---thread identifier, (v) \texttt{comm}---process command name (123 unique values), and (vi) \texttt{ret}---return value for system calls (1026 unique values). This multi-modal representation enables the model to learn correlations between event semantics, timing patterns, and system resource allocation.

\paragraph{Vocabulary and Preprocessing.} We construct global vocabularies for categorical channels (\texttt{event}, \texttt{comm}, \texttt{ret}) by scanning all traces and assigning deterministic integer identifiers ordered by frequency. Event identifiers range from 0--383, with more common events receiving smaller indices. Vocabularies include special tokens for padding (\texttt{\textlangle PAD\textrangle}, ID 0) and unknown values (\texttt{\textlangle UNK\textrangle}, ID 1), and are frozen across all experiments to ensure consistency. Continuous channels (\texttt{dt}) are log-normalized using $\log(1 + \Delta t)$ to reduce scale variance. Thread identifiers are hashed into 256 buckets to control cardinality.

\paragraph{Windowed Sequences.} Kernel traces are inherently long, variable-length streams. To make them suitable for deep generative models, we segment each trace into fixed-length overlapping windows using a sliding window approach. We generate datasets with three context lengths: $L \in \{256, 1024, 4096\}$, enabling systematic evaluation of short-, medium-, and long-context models. Each window contains aligned tensors for all six channels, with shape $(N, L)$ where $N$ is the number of windows per trace and $L$ is the sequence length. This windowed representation serves as the machine-learning-ready input for all models evaluated in this work.

\subsection{Diffusion Model for Multi-Attribute Kernel Traces}
\label{sec:diffusion-model}

We model kernel traces as multi-channel sequences, where each position corresponds to a kernel event and its associated attributes (e.g., event type, CPU, thread identifier, and time delta). Our generator is a Transformer-based denoising diffusion probabilistic model (DDPM) that operates in a continuous latent space while supporting both categorical and continuous channels.

\subsubsection{Feature Embedding and Latent Representation}
\label{sec:feature-embedding}

Let $\mathbf{x}$ denote a windowed trace with length $L$ and a set of channels $\mathcal{C}$ (e.g., \texttt{event}, \texttt{cpu}, \texttt{tid}, \texttt{fd}, \texttt{comm}, \texttt{ret}, and \texttt{dt}). For each discrete channel $c \in \mathcal{C}_{\text{disc}}$, we learn an embedding table $E_c \in \mathbb{R}^{|V_c| \times d}$, where $|V_c|$ is the vocabulary size and $d$ is the model dimension (set to 256 in our experiments). The continuous time-delta channel \texttt{dt} is projected to $\mathbb{R}^{d}$ via a two-layer MLP with SiLU activation. At each sequence position, we form a fused representation by summing the embeddings of all available channels and applying dropout:
\[
\mathbf{h}_0[i] = \sum_{c \in \mathcal{C}_{\text{disc}}} E_c(x_c[i]) \;+\; \mathrm{MLP}_{\text{dt}}(x_{\text{dt}}[i]),
\quad \mathbf{h}_0 \in \mathbb{R}^{L \times d}.
\]
This additive fusion design treats each attribute as a complementary view of the same underlying system state and yields a single unified latent sequence suitable for diffusion. The embedder supports configurable channel subsets, enabling feature ablations without modifying the model core.

\subsubsection{Forward Diffusion Process}
\label{sec:forward-diffusion}

Given the embedded latent sequence $\mathbf{h}_0$, the DDPM forward process progressively corrupts $\mathbf{h}_0$ with Gaussian noise over $T=1000$ diffusion steps. For a timestep $t \in \{0,\dots,T-1\}$, we sample:
\[
\mathbf{h}_t = \sqrt{\bar{\alpha}_t}\,\mathbf{h}_0 + \sqrt{1-\bar{\alpha}_t}\,\boldsymbol{\epsilon},
\quad \boldsymbol{\epsilon} \sim \mathcal{N}(0, I),
\]
where $\bar{\alpha}_t = \prod_{s=0}^{t}\alpha_s$ and $\alpha_t = 1 - \beta_t$ with $\{\beta_t\}$ following a linear schedule from $\beta_{\text{start}}=10^{-4}$ to $\beta_{\text{end}}=0.02$. This standard schedule provides stable corruption while preserving training simplicity.

\subsubsection{Transformer Denoiser with Time Conditioning}
\label{sec:denoiser}

The reverse process is parameterized by a Transformer encoder $\epsilon_{\theta}$ that predicts the injected noise given $(\mathbf{h}_t, t)$. We use sinusoidal timestep embeddings of dimension $d$, followed by a two-layer MLP with SiLU activation to produce a time conditioning vector. This vector is broadcast-added to all sequence positions:
\[
\hat{\boldsymbol{\epsilon}} = \epsilon_{\theta}(\mathbf{h}_t + \mathrm{MLP}_{\text{time}}(\mathrm{SinEmb}(t)), t).
\]
Architecturally, the denoiser consists of 4--8 Transformer encoder layers (depending on configuration) with 4--8 attention heads, operating on sequences of length $L$ with hidden dimension $d=256$. The final layer applies a linear projection to maintain dimensionality. This architecture captures long-range dependencies in kernel traces, where semantically related events may be separated by hundreds to thousands of steps.

\subsubsection{Advanced Training Objectives}
\label{sec:training-objective}

Beyond the standard diffusion loss, we incorporate three complementary objectives to improve generation quality for kernel traces.

\paragraph{Latent Loss.} The primary diffusion objective minimizes mean-squared error between true and predicted noise:
\[
\mathcal{L}_{\text{latent}} = \mathbb{E}_{t,\mathbf{h}_0,\boldsymbol{\epsilon}} \left[ \left\lVert \hat{\boldsymbol{\epsilon}} - \boldsymbol{\epsilon} \right\rVert_2^2 \right].
\]

\paragraph{Reconstruction Loss.} Because kernel traces contain multiple categorical channels that must remain semantically consistent (e.g., event types aligned with CPU/thread context), we compute an auxiliary reconstruction loss from the model's estimate of the clean latent state:
\[
\hat{\mathbf{h}}_0 = \frac{\mathbf{h}_t - \sqrt{1-\bar{\alpha}_t}\,\hat{\boldsymbol{\epsilon}}}{\sqrt{\bar{\alpha}_t}}.
\]
A feature-specific projection head (FeatureUnembedder) maps $\hat{\mathbf{h}}_0$ back to per-channel outputs. Categorical channels are decoded to logits via linear heads and optimized with cross-entropy loss, while the continuous \texttt{dt} channel uses MSE loss:
\[
\mathcal{L}_{\text{recon}} = \sum_{c \in \mathcal{C}_{\text{disc}}} \mathcal{L}_{\text{CE}}(\hat{x}_c, x_c) + \mathcal{L}_{\text{MSE}}(\hat{x}_{\text{dt}}, x_{\text{dt}}).
\]

\paragraph{Repetition-Aware Loss.} Real kernel traces exhibit characteristic repetition patterns (e.g., repeated scheduler events). To encourage the model to match these statistics, we introduce a repetition loss that measures immediate event repetitions. Let $\hat{e} = \arg\max(\text{logits}_{\text{event}})$ denote predicted events. We count consecutive repeats in both predictions and targets, then minimize their L1 distance:
\[
\mathcal{L}_{\text{rep}} = \left| \sum_{i=1}^{L-1} \mathbb{I}[\hat{e}_i = \hat{e}_{i+1}] - \sum_{i=1}^{L-1} \mathbb{I}[e_i = e_{i+1}] \right|.
\]

\paragraph{Transition Frequency Loss.} To preserve realistic event transition patterns, we match the empirical distribution of event transitions. We construct histograms of transition pairs $(e_i, e_{i+1})$ for both predictions and targets, normalize to probability distributions, and minimize KL divergence:
\[
\mathcal{L}_{\text{trans}} = \text{KL}\left( P_{\text{target}}(e_i, e_{i+1}) \,\|\, P_{\text{pred}}(e_i, e_{i+1}) \right).
\]

The final training objective combines all components with fixed weights:
\[
\mathcal{L} = \mathcal{L}_{\text{latent}} + 0.1 \cdot \mathcal{L}_{\text{recon}} + 0.05 \cdot \mathcal{L}_{\text{rep}} + 0.03 \cdot \mathcal{L}_{\text{trans}}.
\]
This multi-objective formulation encourages the latent space to retain attribute-specific information, match statistical properties of real traces, and preserve realistic transition patterns.

\subsubsection{Sampling Strategies}
\label{sec:sampling}

We support two sampling strategies for trace generation.

\paragraph{Standard DDPM Sampling.} To generate synthetic traces, we initialize a latent sequence $\mathbf{h}_T \sim \mathcal{N}(0, I)$ and iteratively apply the reverse diffusion update for $t = T-1, \ldots, 0$:
\[
\mathbf{h}_{t-1} = \frac{1}{\sqrt{\alpha_t}} \left( \mathbf{h}_t - \frac{\beta_t}{\sqrt{1-\bar{\alpha}_t}} \hat{\boldsymbol{\epsilon}} \right) + \sqrt{\beta_t} \boldsymbol{z}, \quad \boldsymbol{z} \sim \mathcal{N}(0, I),
\]
where the noise term is omitted for $t=0$. This requires 1000 denoising steps.

\paragraph{DDIM Fast Sampling.} For efficient generation, we implement DDIM, a deterministic sampling procedure that reduces the number of steps from 1000 to 50 with minimal quality degradation. DDIM uses a non-Markovian reverse process. Given a subsequence of timesteps $\{\tau_1, \ldots, \tau_S\}$ where $S \ll T$, the update rule is:
\[
\mathbf{h}_{\tau_{i-1}} = \sqrt{\bar{\alpha}_{\tau_{i-1}}} \hat{\mathbf{h}}_0 + \sqrt{1 - \bar{\alpha}_{\tau_{i-1}} - \sigma_i^2} \hat{\boldsymbol{\epsilon}} + \sigma_i \boldsymbol{z},
\]
where $\hat{\mathbf{h}}_0 = (\mathbf{h}_{\tau_i} - \sqrt{1-\bar{\alpha}_{\tau_i}} \hat{\boldsymbol{\epsilon}}) / \sqrt{\bar{\alpha}_{\tau_i}}$ and \newline $\sigma_i = \eta \sqrt{(1-\bar{\alpha}_{\tau_{i-1}})/(1-\bar{\alpha}_{\tau_i})} \sqrt{1 - \bar{\alpha}_{\tau_i}/\bar{\alpha}_{\tau_{i-1}}}$. Setting $\eta=0$ yields fully deterministic sampling. This achieves a 20$\times$ speedup over standard DDPM sampling.

After the final denoising step, we decode each channel from the denoised latent sequence $\mathbf{h}_0$. For discrete channels, we apply argmax over predicted logits to obtain integer IDs; for \texttt{dt}, we directly output the predicted continuous values. Generated samples are saved in the same windowed \texttt{.npz} format as training data, enabling direct evaluation under identical preprocessing pipelines.

\subsubsection{Implementation Details}
\label{sec:implementation-notes}

Our implementation consists of three modular components: (i) \texttt{FeatureEmbedder}---a multi-channel embedding layer that maps discrete and continuous inputs to a unified latent space, (ii) \texttt{TransformerDenoiser}---a time-conditioned Transformer encoder that predicts noise, and (iii) \texttt{FeatureUnembedder}---per-channel linear heads that decode latent states to channel-specific outputs. The data loader streams windowed \texttt{.npz} shards and supports configurable channel subsets and sequence lengths, enabling feature ablation and context-length studies within a unified training pipeline. All models are trained using AdamW optimization with a cosine learning rate schedule.




\subsection{Training Procedure}
\label{sec:training}

All models are trained using a unified training pipeline implemented in \texttt{train\_experiment\_better.py} that operates on windowed NPZ trace shards. Each training run uses the same model architecture, diffusion schedule, optimization strategy, and loss formulation described in the previous sections. This ensures that observed differences across experiments can be attributed solely to changes in input context length rather than confounding implementation factors.

\paragraph{Data Loading and Batching.} Training proceeds by streaming windowed sequences from NPZ shards using a custom dataset loader (\texttt{NPZShardDataset}) that supports shard-level caching and multi-worker prefetching. For each mini-batch, sequences are randomly sampled from the training split and embedded into a shared latent space. Batch sizes are adjusted based on sequence length to fit available GPU memory: 64 for $L=256$, 64 for $L=1024$, and 8 for $L=4096$. The loader employs 4 workers with a prefetch factor of 4 and caches up to 8 shards in memory to minimize I/O bottlenecks.

\paragraph{Optimization Strategy.} We use the AdamW optimizer with an initial learning rate of $2 \times 10^{-4}$ and a cosine annealing schedule over the full training duration. For each mini-batch, a diffusion timestep $t$ is sampled uniformly from $\{0, \ldots, T-1\}$, noise is injected according to the forward diffusion process, and the Transformer denoiser is trained to predict the injected noise. The multi-objective loss (latent + reconstruction + repetition + transition) is computed and backpropagated. Gradient norms are monitored and logged to TensorBoard for stability analysis.

\paragraph{Training Configuration.} We train for 20--100 epochs depending on dataset size and convergence behavior. Models are checkpointed after each epoch, and validation loss is computed on a held-out validation set (50 batches) to monitor overfitting. Early stopping is not employed; instead, we retain all checkpoints and select the best-performing one based on validation loss for downstream evaluation. Training employs mixed-precision computation (FP16 or BF16) when available to accelerate training and reduce memory footprint.

\paragraph{Monitoring and Logging.} All training runs are logged to TensorBoard with comprehensive metrics including: (i) training loss components (latent, reconstruction, repetition, transition), (ii) gradient norms, (iii) learning rate, (iv) per-channel reconstruction losses, (v) predicted vs. target repetition counts, and (vi) validation metrics. This enables detailed analysis of training dynamics and identification of convergence issues.

\paragraph{Reproducibility.} All training jobs are executed on a distributed cluster environment (Compute Canada) using Slurm job scripts with fixed random seeds. Hyperparameters are held constant across runs except for sequence length and corresponding batch size adjustments. This design allows controlled comparison of short-, medium-, and long-context training regimes within the same methodological framework.


\subsection{Constraint Learning, Distance Metrics, and Post-hoc Repair}
\label{sec:constraints-repair}

Neural generators can produce sequences that appear locally plausible but violate global system invariants, such as impossible event transitions, inconsistent CPU affinity, or implausible timing relationships. To systematically quantify how far synthetic traces deviate from real system behavior, we introduce a constraint-based evaluation layer that measures distances between generated and real traces with respect to learned invariants extracted from real training data.

\paragraph{Constraint Learning.}
We extract four classes of constraints from real traces to characterize valid kernel execution patterns:

\begin{enumerate}
  \item \textbf{Event transition constraints.} A directed event transition graph $\mathcal{G} = (V, E)$ is constructed, where $V$ corresponds to event types and $(e_i, e_j) \in E$ if event $e_j$ directly follows $e_i$ in at least one real trace. This captures valid event orderings.
  
  \item \textbf{Temporal constraints.} For each event type $e$, we learn empirical bounds over inter-event time deltas by collecting all observed values: $\{\Delta t_{\min}^{(e)}, \Delta t_{\max}^{(e)}, \mathcal{T}_e\}$, where $\mathcal{T}_e$ is the set of observed time deltas for event $e$.
  
  \item \textbf{CPU affinity constraints.} For each event type $e$, we record the set of CPUs on which it was observed: $\mathcal{C}_e$. This captures scheduling locality patterns.
  
  \item \textbf{Attribute validity constraints.} For each event type, we learn allowed categorical values for thread identifiers, file descriptors, process commands, and return values by collecting all observed values across the dataset.
  
  \item \textbf{Event frequency distribution.} Empirical probabilities $P(e)$ are computed by counting event occurrences and normalizing by total event count. These serve as reference distributions for probabilistic repair.
\end{enumerate}

All constraints are learned once from the complete real dataset and frozen across all experiments to ensure consistency.

\paragraph{Constraint-Based Distance Metrics.}
Given a synthetic trace $\hat{X}$ and the learned constraints, we compute distance metrics that quantify deviation from real-system behavior:

\emph{Transition distance} measures the fraction of invalid event transitions:
\[
D_{\text{trans}}(\hat{X}) = 1 - \frac{1}{|\hat{X}|-1} \sum_{t} \mathbb{I}\left[(\hat{e}_t, \hat{e}_{t+1}) \in \mathcal{G}\right].
\]

\emph{Temporal distance} measures the fraction of events whose inter-event time lies outside learned bounds:
\[
D_{\text{time}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\Delta t_t \notin [\min_e, \max_e]\right].
\]

\emph{CPU affinity distance} measures the fraction of events assigned to invalid CPUs:
\[
D_{\text{cpu}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\hat{cpu}_t \notin \mathcal{C}_{\hat{e}_t}\right].
\]

\emph{Attribute validity distance} aggregates violations across categorical attributes:
\[
D_{\text{attr}}(\hat{X}) = \frac{1}{|\hat{X}|} \sum_{t} \mathbb{I}\left[\exists a \in \mathcal{A} : \hat{a}_t \notin \mathcal{V}_{\hat{e}_t}^{(a)}\right].
\]

These metrics collectively characterize how far synthetic traces deviate from real execution constraints.

\paragraph{Post-hoc Repair.}
Using the learned constraints, we implement a greedy forward repair procedure that processes each trace in two passes:

\textbf{Pass 1: Event Transition Repair.} For each position $t$, we check if the transition $(e_t, e_{t+1})$ exists in $\mathcal{G}$. If invalid, we replace $e_{t+1}$ with a valid successor sampled probabilistically from $\mathcal{G}(e_t)$ using event frequency weights $P(e)$. When an event is replaced, its associated time delta is updated by sampling from the allowed time delta set $\mathcal{T}_{e_{t+1}}$.

\textbf{Pass 2: CPU Affinity Repair.} For each event $e_t$, we verify that the assigned CPU $c_t$ belongs to the event-conditioned allowed set $\mathcal{C}_{e_t}$. If $c_t \notin \mathcal{C}_{e_t}$, we replace it with a randomly sampled CPU from $\mathcal{C}_{e_t}$.

Repair is applied uniformly as a post-processing step across all configurations. The same constraint-based distance metrics are computed before and after repair to quantify repair effectiveness.


\subsection{Evaluation Metrics}
\label{sec:evaluation-metrics}

We evaluate downstream predictor performance using six complementary metrics, each capturing different aspects of prediction quality. All metrics are computed on the held-out real test set to measure how well models trained on synthetic data generalize to real system behavior.

\textbf{F1-Score (Macro).} Our primary metric is the macro-averaged F1-score, which treats all event classes equally regardless of frequency. For each event class $c$, we compute precision and recall:
\[
\text{Precision}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c}, \quad
\text{Recall}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FN}_c},
\]
where $\text{TP}_c$, $\text{FP}_c$, and $\text{FN}_c$ denote true positives, false positives, and false negatives for class $c$. The per-class F1-score is the harmonic mean:
\[
\text{F1}_c = 2 \cdot \frac{\text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c}.
\]
The macro-averaged F1-score is the unweighted mean across all $N=384$ event classes:
\[
\text{F1-macro} = \frac{1}{N} \sum_{c=1}^{N} \text{F1}_c.
\]
We select F1-macro as our primary metric because kernel traces exhibit severe class imbalance: common events (e.g., scheduler switches, memory allocations) occur orders of magnitude more frequently than rare but critical events (e.g., errors, security violations, I/O failures). Macro-averaging ensures that rare events contribute equally to the overall score, preventing models from achieving high accuracy by simply predicting frequent classes while ignoring rare but operationally significant events.

\textbf{F1-Score (Weighted).} As a secondary metric, we report weighted F1-score, which averages per-class F1 scores weighted by class support (number of true instances):
\[
\text{F1-weighted} = \frac{1}{|\mathcal{D}|} \sum_{c=1}^{N} n_c \cdot \text{F1}_c,
\]
where $n_c$ is the number of test samples with true label $c$ and $|\mathcal{D}|$ is the total test set size. This metric reflects overall prediction quality while accounting for class distribution, providing a complementary view to macro-averaging.

\textbf{Accuracy.} We report standard classification accuracy, defined as the fraction of correct predictions:
\[
\text{Accuracy} = \frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \mathbb{I}[\hat{y}_i = y_i],
\]
where $\hat{y}_i$ and $y_i$ are the predicted and true labels. While accuracy is intuitive, it can be misleading under class imbalance, as models can achieve high accuracy by overpredicting frequent classes.

\textbf{Top-K Accuracy.} To assess whether the model captures plausible alternatives even when the top prediction is incorrect, we compute top-5 and top-10 accuracy:
\[
\text{Top-K Acc} = \frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \mathbb{I}[y_i \in \text{TopK}(\mathbf{p}_i)],
\]
where $\text{TopK}(\mathbf{p}_i)$ denotes the set of $K$ event classes with highest predicted probabilities for sample $i$. These metrics are particularly relevant for kernel traces, where multiple valid next events may exist depending on runtime conditions (e.g., different scheduler decisions, I/O completion ordering).

\textbf{Cross-Entropy Loss.} We report the average cross-entropy loss to quantify prediction confidence:
\[
\text{Loss} = -\frac{1}{|\mathcal{D}|} \sum_{i=1}^{|\mathcal{D}|} \log p(y_i \mid \mathbf{x}_i),
\]
where $p(y_i \mid \mathbf{x}_i)$ is the predicted probability of the true class. Lower loss indicates higher confidence in correct predictions, complementing discrete accuracy metrics with a continuous measure of prediction quality.

\paragraph{Experimental Configurations.} For each diffusion model configuration, we train downstream predictors on four datasets: (i) \textbf{Real only}---baseline using only real training data, (ii) \textbf{Synthetic only}---trained entirely on synthetic data, (iii) \textbf{Combined (repaired)}---50/50 mix of real and constraint-repaired synthetic data, and (iv) \textbf{Combined (no repair)}---50/50 mix of real and raw synthetic data. All predictors are evaluated on the same held-out real test set to measure synthetic data utility.
