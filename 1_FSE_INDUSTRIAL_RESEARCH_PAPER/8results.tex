\section{Results}
\label{sec:results}

We organize results around four research questions (RQ1--RQ4) using a downstream next-event prediction task. Unless otherwise stated, models are evaluated on the held-out real test split, and we report macro-F1 as the primary metric, with accuracy and Top-5 accuracy as secondary metrics.

\subsection{RQ1: For which workload types can synthetic data effectively double training dataset size?}
\label{sec:rq1}

To evaluate the practical utility of synthetic data augmentation, we simulate a scenario where real data collection is expensive and we seek to double the training dataset size using synthetic data. We compare downstream task performance when training on: (i) \textbf{Real-only (50\% data)}: baseline using only real training data, and (ii) \textbf{Combined (100\% data)}: 50\% real + 50\% constraint-repaired synthetic data. This setup quantifies the performance trade-off for doubling dataset size with synthetic augmentation.

Table~\ref{tab:rq1} presents F1-Macro scores across six benchmarks and three context lengths, along with the performance degradation ($\Delta$F1) when using synthetic augmentation.

At L=4096, scimark2 achieves 87.2\% F1-Macro with 2$\times$ data, only 2.6 percentage points below the real-only baseline (89.8\%), while I/O-heavy workloads (stream, iozone, unpack-linux) show significant degradation (25--36\%). Table~\ref{tab:rq2} shows that constraint-guided repair provides positive impact in 12 out of 15 benchmark-context combinations (80\%), with improvements ranging from +0.3\% to +4.3\%. The two best cases are scimark2 @ L=256 (+4.3\%) and pybench @ L=256 (+4.1\%). Only 3 cases show degradation, with ffmpeg showing slight negative effects (-0.1\% to -3.6\%) and unpack-linux @ L=4096 exhibiting a likely data anomaly (-24.6\%). Repair is most effective at L=256 (average +1.5\% relative improvement) compared to L=1024 (+0.6\%) and L=4096 (-4.2\%, skewed by anomaly; excluding anomaly: +0.5\%). This pattern suggests that diffusion models trained on shorter contexts produce more constraint violations, which repair can effectively fix.

\subsection{RQ3: How does increasing diffusion model context length improve synthetic data quality?}
\label{sec:rq3}

To evaluate the impact of temporal context on synthetic data quality, we compare downstream task performance when training on Combined (Repaired) data generated by diffusion models trained with different context lengths: $L \in \{256, 1024, 4096\}$. This isolates the effect of context length while controlling for repair and augmentation.

Table~\ref{tab:rq3} presents F1-Macro scores across six benchmarks and three context lengths, along with the absolute and relative improvements from L=256 to L=4096.

Table~\ref{tab:rq3} shows that increasing context length from L=256 to L=4096 improves synthetic data quality across all benchmarks, with an average gain of +29.9 percentage points (+104\% relative improvement). Every benchmark shows substantial gains, with improvements ranging from +16.0\% (unpack-linux) to +46.6\% (scimark2). Deterministic, structured workloads show the largest improvements: scimark2 achieves +46.6\% gain (40.6\% → 87.2\%, +115\% relative), reaching near-parity with real-only performance (89.8\%), while pybench gains +36.5\% (+87\% relative) and ffmpeg gains +32.3\% (+101\% relative). Even I/O-heavy workloads benefit substantially: stream improves by +27.4\% (+156\% relative), iozone by +20.9\% (+105\% relative), and unpack-linux by +16.0\% (+57\% relative). The diminishing returns pattern (L=256→1024: +22.9\%, L=1024→4096: +7.0\%) suggests that L=4096 may be near-optimal for current hardware constraints.

\subsection{RQ4: Can simpler diffusion models (fewer channels) achieve comparable synthetic data quality with lower computational cost?}
\label{sec:rq4}

To evaluate the cost-effectiveness of diffusion model complexity, we conduct a cross-model ablation study on three diverse benchmarks (ffmpeg, pybench, scimark2). We train diffusion models with three channel configurations: (i) \textbf{Base}: event + dt (2 channels), (ii) \textbf{System}: event + dt + cpu + tid (4 channels), and (iii) \textbf{Full}: event + dt + cpu + tid + comm + ret (6 channels). For each diffusion model, we train downstream predictors using all compatible channel subsets, creating a cross-evaluation matrix that isolates both diffusion model channel importance and predictor channel importance.

Within each diffusion model, varying the predictor's channel configuration produces only 1--3\% F1 variation, indicating that predictor channel choice has minimal impact on downstream performance.
