\section{Evaluation}
\label{sec:evaluation}

This section evaluates the effectiveness, robustness, and cost–quality trade-offs of \textsc{SynthTrace}. Our evaluation is structured around four research questions:

\begin{itemize}[leftmargin=*]
  \item \textbf{RQ1:} When can synthetic kernel traces safely augment limited real training data?
  \item \textbf{RQ2:} Does constraint-guided repair consistently improve synthetic data quality?
  \item \textbf{RQ3:} How does increasing diffusion model context length affect synthetic data quality?
  \item \textbf{RQ4:} Can simpler diffusion models achieve comparable quality with lower computational cost?
\end{itemize}

All research questions are evaluated using a controlled downstream next-event prediction task on held-out real kernel traces. This setup enables direct assessment of whether models trained on synthetic data generalize to real system behavior.

\subsection{Compute Environment and Datasets}

All experiments were executed on the Nibi high-performance computing cluster. Each training and sampling job was allocated a single NVIDIA H100 GPU with 80\,GB of device memory, along with 8 CPU cores and 32\,GB of host memory. Mixed-precision training with \texttt{bf16} and TF32 acceleration was enabled to maximize throughput while maintaining numerical stability.

We use windowed NPZ datasets derived from real LTTng kernel traces, as described in Section~\ref{sec:data-preprocessing}. Each dataset consists of fixed-length event sequences extracted from the \texttt{all-events} tracing configuration and split into training, validation, and test partitions. Unless otherwise stated, experiments are conducted on the \texttt{scimark2} benchmark, which we use as a representative workload due to its diverse compute, scheduling, and memory behavior.

\subsection{Model and Training Configuration}
\label{sec:model-config}

All experiments use the same diffusion-model architecture to isolate the effects of temporal context length and feature availability. The denoising network is a Transformer encoder with embedding dimension $d_{\text{model}}=256$, 4--8 attention heads, and 4--8 layers depending on configuration. The diffusion process uses $T=1000$ timesteps with a linear noise schedule from $\beta_{\text{start}}=10^{-4}$ to $\beta_{\text{end}}=0.02$.

Models are optimized using AdamW with an initial learning rate of $2 \times 10^{-4}$ and cosine decay. Aside from the experimental variables described below, all architectural and optimization hyperparameters are held constant across runs. \subsection{Sampling and Synthetic Data Generation}

For each trained diffusion model, we generate synthetic kernel traces using DDIM sampling with 50 denoising steps starting from Gaussian noise. For each configuration, we generate 10{,}000 synthetic samples and store them in the same windowed NPZ format as real traces, ensuring identical downstream preprocessing.

\paragraph{Constraint Reference.}
System-level validity is assessed using a universal constraint knowledge base mined from all real NPZ shards (training, validation, and test) using parallel processing. All repair experiments and validity measurements use the same file to ensure consistent and reproducible evaluation (RQ2).

\subsection{Downstream Task Evaluation}
\label{sec:downstream-eval}

All research questions are evaluated using a downstream next-event prediction task. This task measures whether predictors trained on synthetic traces can generalize to real kernel execution behavior.

\paragraph{Task Definition.}
Given a sequence of $L_{\text{pred}}=128$ consecutive kernel events, the model predicts the next event type (384-way classification). This task requires modeling both local event patterns and longer-range system dependencies.

\paragraph{Predictor Architecture.}
The downstream predictor is a Transformer-based classifier with $d_{\text{model}}=256$, 8 attention heads, and 4 layers. For multi-channel inputs, features are embedded separately, concatenated, and fused via a linear projection. The final hidden state is passed through a two-layer MLP to produce event logits.

\paragraph{Training Configuration.}
Predictors are trained for up to 20 epochs using AdamW ($\text{lr}=10^{-4}$) with cross-entropy loss. Training employs sliding windows with stride 64, batch size 64, and early stopping with patience 3 based on validation macro-F1. All predictors are evaluated on the same held-out real test set.

\paragraph{Training Set Configurations.}
For each diffusion model configuration, downstream predictors are trained under four data conditions:
(i) \textbf{Real-only} (baseline),
(ii) \textbf{Synthetic-only},
(iii) \textbf{Combined (Repaired)}: a 50/50 mix of real and constraint-repaired synthetic traces, and
(iv) \textbf{Combined (No Repair)}: a 50/50 mix of real and unrepaired synthetic traces.
All predictors are evaluated on the same real-only test set to ensure fair and consistent comparison.

\subsection{Evaluation Metrics}
\label{sec:evaluation-metrics}

We evaluate downstream predictor performance using multiple complementary metrics, each capturing a different aspect of prediction quality. All metrics are computed on the same held-out real test set to assess how well models trained on synthetic data generalize to real system behavior.

\paragraph{F1-Score (Macro).}
Our primary evaluation metric is the macro-averaged F1-score, which treats all event classes equally regardless of their frequency. For each event class $c$, we compute precision and recall as:
\[
\text{Precision}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c}, \quad
\text{Recall}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FN}_c},
\]
and the corresponding F1-score:
\[
\text{F1}_c = 2 \cdot \frac{\text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c}.
\]
The macro-F1 score is then computed as the unweighted average over all $N=384$ kernel event classes:
\[
\text{F1-macro} = \frac{1}{N} \sum_{c=1}^{N} \text{F1}_c.
\]

We select macro-F1 as the primary metric because kernel execution traces exhibit severe class imbalance. Frequent events (e.g., scheduler activity) dominate execution, while rare events (e.g., error paths or I/O corner cases) are often operationally critical. Macro-averaging prevents models from achieving deceptively high scores by overpredicting frequent events while failing to capture rare but important behaviors.

\paragraph{F1-Score (Weighted).}
We additionally report weighted F1-score, which averages per-class F1 scores weighted by class support. This metric reflects overall prediction quality under the natural event frequency distribution and complements macro-F1 by indicating how well models perform on common execution paths.

\paragraph{Accuracy.}
Standard classification accuracy is reported for completeness. Because accuracy can be misleading under heavy class imbalance, we interpret it alongside F1-based metrics rather than in isolation.

\paragraph{Top-$K$ Accuracy.}
To assess whether models capture plausible alternative behaviors even when the top prediction is incorrect, we report Top-5 and Top-10 accuracy. These metrics are particularly relevant for kernel traces, where multiple valid next events may occur due to scheduling nondeterminism or I/O interleavings.
