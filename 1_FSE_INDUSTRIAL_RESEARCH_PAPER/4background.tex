\section{Background and Motivation}
\label{sec:background}

This section provides background on kernel execution traces and diffusion-based sequence modeling, and motivates the design principles underlying \textsc{SynthTrace} from an industrial systems perspective.

\subsection{Kernel Execution Traces}
\label{sec:bg-traces}

Kernel execution traces record low-level system events as they occur during program execution~\cite{Noferesti2024Enhancing, Njoku2025Kernel-Level, Giraldeau2016Wait, Gebai2018Survey}. Unlike application logs, which record high-level operations at developer-specified points, kernel traces provide a comprehensive view of system behavior: process scheduling, memory allocation, file system operations\cite{Naas2021EZIOTracer}, network I/O\cite{Gellé2021Combining}, and inter-process communication\cite{Giraldeau2016Wait, Gellé2021Combining}.

Modern Linux systems support kernel tracing through several frameworks, such as LTTng (Linux Trace Toolkit Next Generation)~\cite{Desnoyers2006The, Beamonte2015Linux}, eBPF~\cite{eBPF}, and \texttt{ftrace}. In this work, we use LTTng, which offers high-throughput tracing with low runtime overhead and fine-grained control over event selection~\cite{Desnoyers2006The}. A typical LTTng trace contains millions of events per minute of execution. Each event records a high-resolution timestamp, an event type (drawn from hundreds of kernel event categories), the CPU core on which the event occurred, process metadata such as thread and process identifiers, and event-specific payload fields including return values, memory addresses, file descriptors, or scheduling parameters.

These attributes are tightly coupled: event types constrain which payload fields are present, CPU affinity reflects scheduler decisions, and timing patterns vary across workload phases and system states. As a result, realistic modeling of kernel traces requires capturing multi-dimensional dependencies across event semantics, temporal dynamics, and resource usage.

Despite their diagnostic value, collecting kernel execution traces at scale in production environments is often impractical. Continuous kernel tracing can incur significant storage overhead, increase I/O pressure, and raise operational or privacy concerns, particularly in multi-tenant, safety-critical, or resource-constrained systems. Consequently, engineers frequently rely on limited trace samples collected under controlled conditions. Such datasets may fail to capture rare execution paths, workload diversity, or long-tail system behaviors, limiting their usefulness for developing, validating, and stress-testing trace-driven system analysis tools.

\subsection{Diffusion Models for Sequence Generation}
\label{sec:bg-diffusion}

Denoising diffusion probabilistic models (DDPMs)~\cite{ho2020denoisingdiffusionprobabilisticmodels} have emerged as a powerful class of generative models capable of learning complex data distributions. Unlike autoregressive models that generate sequences token by token, diffusion models operate by iteratively denoising a corrupted signal\cite{Song2020Denoising}, enabling parallel generation and improved modeling of global structure.

The diffusion process consists of two phases. In the \emph{forward process}\cite{Arriola2025Block, sutskever2014sequencesequencelearningneural}, Gaussian noise is progressively added to data samples over a fixed number of timesteps until the original signal is fully obscured. In the \emph{reverse process}, a neural network is trained to predict and remove the injected noise at each step, gradually reconstructing samples drawn from the learned data distribution.

For sequential data, Transformer-based architectures~\cite{vaswani2023attentionneed} are commonly used as denoisers due to their ability to model long-range dependencies via self-attention. This capability is particularly relevant for kernel traces, where semantically related events—such as a system call entry and its corresponding exit, or repeated scheduling patterns—may be separated by hundreds or thousands of intervening events. These properties make diffusion models a natural fit for modeling long, structured execution traces.

\subsection{Motivation for Constraint-Guided Generation}
\label{sec:bg-motivation}

While neural generative models can capture rich statistical regularities, statistical plausibility alone is insufficient for kernel execution traces. Trace-driven system analysis tools implicitly assume that traces respect fundamental execution invariants imposed by the operating system, scheduler, and hardware. Violating these invariants yields traces that are not merely low-quality, but semantically impossible, making them unsafe for debugging, validation, or training purposes.

Common classes of violations include: (i) \emph{invalid event transitions}, such as a system call exit without a corresponding entry; (ii) \emph{temporal violations}, where inter-event delays fall outside feasible ranges observed on real systems; and (iii) \emph{attribute inconsistencies}, such as events occurring on CPU cores or process contexts never observed for those event types. Even infrequent violations can mislead downstream tools, causing incorrect diagnoses or masking true system behaviors.

Relying solely on a generative model to implicitly learn and respect such constraints is brittle, particularly when training data is limited or skewed. To address this, \textsc{SynthTrace} adopts a hybrid approach that explicitly mines execution invariants from real traces and enforces them through a post-hoc validation and repair layer. This design separates statistical diversity from correctness enforcement, allowing the generator to explore a broad space of behaviors while ensuring that final outputs remain consistent with real-system semantics. Preserving these invariants is a prerequisite for the safe use of synthetic kernel traces in downstream system-analysis workflows.
